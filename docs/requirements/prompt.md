## 1. プロジェクト概要
- **プロジェクト名**: seaweed
- **背景・課題**: 手持ちのお金に対する日々の収支やキャッシュフローが管理できていない。支出の発生と、クレジットカード等による実際の資金流出のタイミングがずれている。
- **目的・ゴール**:
  - 生活資金の現状および将来の予測を可視化し、生活レベルを適正化する。
  - サブスクリプションと投資の実行記録を一元管理し、固定費の見直しおよび投資判断の振り返りを可能にする。
- **実現したい可視化のイメージ（例）**:
  - 「現在の生活費だと毎月〇円貯金でき、いつ頃にX万円に到達する」という予測チャートの表示。
  - 「Y万円まで貯めたい場合、生活費をあと〇〇円削る必要がある」といった逆算の提示。到達希望時期は任意（設定しているときだけ逆算する）。
  - 当月（既定）の支出を費目別に内訳表示し、何が厚いかを把握できるようにする。

## 2. 対象ユーザー・関係者
- **利用者**: 自分のみ（1名）
- **ステークホルダー**: 外部の承認者・運用担当はなし（意思決定者は利用者本人）

## 3. スコープ（対象範囲）
- **今回実装する範囲（In Scope）**:
  - 認証: 簡易ログイン。到達制御はインターネット非公開の閉域（Tailscale）。アプリ内の許可IPリストは持たない
  - 家計簿: 収支の登録・編集・削除。発生日と資金決済日（支払いラグ）、支払手段、費目
  - 手元資金の登録・更新（予測の起点）
  - 定期収入（給与等）の登録・編集・削除
  - 貯蓄目標の設定（到達希望時期は任意）
  - 分析ダッシュボード: 現状把握、費目別支出内訳、将来予測チャート、条件付き逆算
  - 利用中サブスクの登録・一覧・編集・削除
  - 投資実行記録（いつ、どの銘柄、理由、単価、数量）の登録・一覧・編集・削除
- **今回対象外とする範囲（Out of Scope）**:
  - パスワード変更機能
  - 家計簿の分析ダッシュボードにおけるAI活用
  - 株式関連ニュース・RSS、株価・為替の自動取得、時価評価、売却・損益計算
  - 金融機関・カード・証券とのAPI連携、明細の自動取込
  - 家計簿へのサブスク／定期収入の自動仕訳
  - 費目・支払手段のマスタ編集画面（初期は固定選択肢）
  - インターネットへのサービス公開、独自ドメイン、公開用HTTPS
  - 複数ユーザー、ネイティブアプリ、既存データ移行、RDS・高可用性

## 4. 機能要件・非機能要件
- **データの役割分担（予測の二重計上を防ぐ）**:
  - 定期収入マスタ: 給与等の繰り返し収入。予測の収入に使う。家計簿に毎月の給与は書かない
  - サブスクマスタ: 固定費。予測の固定費に使う。家計簿に毎月の引落は書かない
  - 家計簿: 変動支出と臨時収入の実績。予測の変動費は直近の完了暦月の平均（当月途中は混ぜない）
  - 手元資金: 手動更新の起点残高。家計簿の決済で自動増減させない
  - 投資記録: 実行の台帳。時価は予測残高に加えない。現金の移動は家計簿の投資拠出で表す
- **主要な機能要件**:
  - **認証機能**: 閉域からの到達＋識別子とパスワードによる簡易ログイン。ログアウトあり。パスワード変更UIはなし
  - **家計簿管理機能**: 収支のCRUD。発生日と資金決済日を独立して持つ。支払手段・費目は固定選択肢。クレジットカード時は資金決済日を必須とする
  - **手元資金・定期収入・貯蓄目標**: 予測に必要な入力。到達希望時期は空でもよい
  - **分析ダッシュボード機能**:
    - 現状の収支サマリと、費目別の支出内訳（期間はサマリと同一、既定は当月、資金決済日ベース）
    - 将来の手元資金推移チャート。見込（月次貯金額）に加え、資金決済日が未来の家計をその決済タイミングで反映する
    - 目標額があれば到達時期を示す。到達希望時期があるときだけ、必要な生活費削減額を逆算する
  - **サブスク管理機能**: 名称・金額・周期・支払日のCRUD。年額は月割りして固定費に載せる
  - **投資管理機能**: 投資日・銘柄・理由・単価・数量のCRUD。投入金額は単価×数量で表示する
- **非機能要件**:
  - 可用性・負荷分散・高度なセキュリティ（MFA、WAF、公開TLS等）は求めない
  - 個人利用・単一EC2を前提に、設計が成立する最小限（タイムゾーンJST、文字コードUTF-8、パスワードの平文保存禁止）は要件化する
  - 金額・単価・数量はDECIMALで保持する。v1の入力・表示は日本円。他通貨の切替UIは作らない
  - 通信の機密性は閉域（Tailscale）に委ね、公開用の証明書・ドメインは持たない

## 5. 前提条件・制約事項
- **技術スタック**:
  - フロントエンド: React
  - バックエンド: Java (Spring Boot)
  - DB: MySQL
- **予算・スケジュール**:
  - 2026年9月中のリリースを目指す
- **インフラ・その他制約**:
  - AWS EC2上で動作させる
  - コストおよび構成の簡略化のため、Amazon RDSは使用せず、EC2インスタンス上に直接DBサーバーをインストールして運用する
  - サービスはインターネットに公開しない。利用者端末とEC2をTailscaleで閉域接続する
  - 管理用SSHの送信元制限はセキュリティグループで行い、アプリに入れない状態でもAWSコンソールから復旧できるようにする
