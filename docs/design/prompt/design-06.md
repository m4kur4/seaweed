例: プロセス構成、URL/API パス、画面項目、ステータスコード、テーブル列と型、計算の手順、設定キー。
要件定義書の章のコピーや、未決定のままの「設計で定める」の持ち越しはしない。
判断が必要なら設計側で 1 つ選び、「設計判断:」と理由を短く残す。

- 要件にない機能の追加
- 公開 TLS、RDS、許可 IP リスト、時価自動取得など、対象外の復活
- この指示で複数ファイルを出力すること

`docs/design/md/テーブル定義書.md` を 1 ファイルだけ作成しました。別ファイルの `.sql` は出していません（DDL は文書内にあります）。

固定した内容は次のとおりです。

- **6 表:** `ledger_entry` / `subscription` / `investment_record` / `recurring_income` / `cash_on_hand` / `savings_goal`。FK なし、ユーザ表なし
- **金額** `DECIMAL(15,2)`、単価 `(15,4)`、数量 `(18,6)`。投入額・月額換算は列に持たない
- **singleton** は `id=1`。初期行は手元資金 `0` + `updated_on NULL`、目標は両方 NULL
- **索引:** 家計は発生日・決済日それぞれ。一覧の名称・投資日
- JPA は `ddl-auto=none`。適用は文書の SQL を手実行

No.7 処理仕様書は、これらの列だけを読んで計算を書けます。
