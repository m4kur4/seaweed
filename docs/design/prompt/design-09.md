@docs/design/
【依頼】
設計成果物一覧の No.9「インフラ設計書」を、指定のファイル名で 1 ファイルだけ作成してください。
他の設計書・コード・DDL は作らないでください。
【入力】
- 要件の正は要件定義書とする。
- すでに docs/design にある設計書がある場合はそれに従い、矛盾する決め方をしない。
- 成果物一覧に「今回作らない」とある文書の範囲は書かない（他文書へ一文で委譲する）。
【粒度】
あとからこの設計書（と要件定義書）を入力にコーディングする。
そのため、方針の繰り返しではなく、実装者が迷わない決めを書くこと。
例: プロセス構成、URL/API パス、画面項目、ステータスコード、テーブル列と型、計算の手順、設定キー。
要件定義書の章のコピーや、未決定のままの「設計で定める」の持ち越しはしない。
判断が必要なら設計側で 1 つ選び、「設計判断:」と理由を短く残す。
【禁止】
- 要件にない機能の追加
- 公開 TLS、RDS、許可 IP リスト、時価自動取得など、対象外の復活
- この指示で複数ファイルを出力すること

特に @docs/design/md/システム構成設計書.md のポート・パス・待受の決めに合わせること。
出力先は@docs/design/md で、.md形式としてください。
