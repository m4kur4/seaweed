## 1. ひとことで

**seaweed** は、利用者 1 名のための家計・固定費・投資記録の Web アプリです。インターネット上の公開サイトにはしません。利用者の端末とサーバを Tailscale（閉域の遠隔アクセス）でつなぎ、そのうえでログインして使います。

本番は AWS 上の仮想サーバ **1 台** に、画面・業務処理・データベースを同居させます。銀行・カード・証券との自動連携、株価の時価、スマホ専用アプリ、高可用性は対象外です。リリース目標は **2026 年 9 月中** です。

## 2. 誰が・何のために使うか

| 項目 | 内容 |
| --- | --- |
| 利用者 | 本人 1 名。権限の違う管理者／一般の区別はない |
| 端末 | 主にデスクトップの Chrome。Tailscale 経由のスマホブラウザは可だが、専用画面は作らない |
| 目的 | いまの手元資金と、今の生活を続けた場合の将来残高を見えるようにする。サブスクと「いつ・なぜ買ったか」の投資記録を一箇所に残す |
| 成功のイメージ | 発生日と引落日の両方で家計を残せる。ダッシュボードで当月の内訳・貯金額・到達時期（目標があるとき）・希望時期があるときの削減額が見える |

既存の家計ソフトや銀行からのデータ移行はありません。稼働後、画面から自分で登録します。

## 3. できること

| 機能 | 利用者ができること |
| --- | --- |
| ログイン | 識別子とパスワードで入る。ログアウトできる。パスワード変更画面はない |
| 家計簿 | 支出・臨時収入の登録・修正・削除・期間一覧。費目と支払手段は固定の選択肢。クレジットカードは引落日（資金決済日）が必須 |
| サブスク | 名称・金額・月額／年額・支払日の登録・一覧・修正・削除。家計簿への自動仕訳はしない |
| 定期収入 | 給与などの見込みをマスタとして登録・修正・削除。家計簿の「収入」とは別 |
| 投資記録 | いつ・銘柄・理由・単価・数量。投入額は単価×数量で自動表示。時価・売却は扱わない |
| 設定 | 手元資金（現預金の合計 1 件）と貯蓄目標。到達希望の年月は任意 |
| ダッシュボード | 手元資金、期間の実績収支、費目内訳、サブスク月額合計、定期収入月額合計、投資の件数と投入総額、将来残高のチャート、目標到達時期、希望時期があるときの削減額 |

金額は日本円、内部は小数を持てる形です。通貨切替の画面はありません。

## 4. 今回つくらないこと

発注範囲に含めないもの（要件の対象外）。後から足すときは要件と設計の改訂が先です。

- インターネット公開、独自ドメイン、公開用の HTTPS（証明書）
- 銀行・カード・証券 API、株価の自動取得、含み損益
- パスワード変更・リセットの画面、多要素認証、IP 許可リスト
- 帳票 PDF、バッチ処理、複数ユーザー・権限
- Amazon RDS、負荷分散装置、オートスケール、死活監視の仕組み
- 既存データからの自動移行

## 5. 画面の全体像

使うアドレスは **`http://seaweed/`**（Tailscale の名前解決）。`https://` では開きません。

| 画面 | 役割 |
| --- | --- |
| ログイン | 入室。未ログインで他の画面を開くとここに戻る |
| ダッシュボード | 見る専用。ここから数値を書き換えない |
| 家計簿 | 一覧と入力が同じ画面 |
| サブスク / 定期収入 / 投資 | 各マスタ・記録の一覧と入力が同じ画面 |
| 設定 | 手元資金と貯蓄目標 |

給与や動画配信などの固定の出入りは、家計簿ではなく **定期収入マスタ / サブスクマスタ** に書きます。家計簿の支出は食費などの変動が中心です。この役割分担が、あとで述べる予測の前提です。

## 6. 数字の考え方（予測）

ダッシュボードの「実績」と「予測」は別物です。

- **実績:** 選んだ期間の家計簿だけ。既定は当月、資金決済日ベース。費目内訳も同じ期間の家計簿支出だけ（サブスクマスタは足さない）。
- **予測の収入:** 定期収入マスタの月額換算だけ。家計簿に書いた臨時収入は予測に入れない。
- **予測の固定費:** サブスクマスタの月額換算だけ。
- **予測の変動費:** 直近の「終わった暦月」最大 3 ヶ月のうち、支出があった月だけの平均。当月は入れない。
- **手元資金:** 利用者が設定画面で入れた残高が起点。未登録のあいだチャートは出さない。
- **未来のクレカ引落など:** 資金決済日が先の家計は、その月のチャートに反映する。
- **投資記録:** 件数と投入総額の表示のみ。将来残高には足さない（現金が減る話は家計簿の「投資拠出」で表す）。
- **逆算（あといくら削るか）:** 目標額があり、かつ到達希望の年月を入れているときだけ。希望が空なら出さない。

年額は 12 で割って月額にします。予測は直線的な目安であり、実態とずれることがあります。確定の引落と見込の変動費が同じ月に重なる補正は、今回はしません。

## 7. どこから・どう守るか

防御は 2 段です。

1. **網:** サービスは Tailscale の内側だけ。仮想サーバのアプリ用ポートをインターネット全体には開けません。自宅 IP の許可リストはアプリに持ちません（外出先・IP 変動は Tailscale 側で吸収する）。
2. **ログイン:** 閉域に入れても、識別子とパスワードが必要です。セッションは約 14 日間（サーバ再起動で切れます）。パスワードは画面では変えられません。サーバ上の設定を直してプロセスを再起動します。

公開用の証明書は使いません。端末〜サーバの途中の盗み見対策は Tailscale の暗号化に任せます。閉域の内側は HTTP のままです。

管理用の SSH は、インターネット側でポート 22 を開けますが、送信元は自宅などの 1 つの住所（`/32`）に限ります。自宅のグローバル IP が変わって入れなくなったときは、AWS の画面からその制限だけ直します。アプリが止まっていても、この経路でサーバに入れます。

## 8. 動かしている箱

| 項目 | 設計上の決め |
| --- | --- |
| 場所 | AWS 東京リージョン。仮想サーバ 1 台 |
| 中身 | 画面つきのアプリと、MySQL。データベース専用サービス（RDS）は使わない |
| 入口 | Tailscale が 80 番を受け、中のアプリ（本機の 8080 番。外からは見えない）へ渡す |
| 負荷分散・予備機 | なし。止まったらその間は使えない |
| 開発用 PC | 本番の閉域は必須にしない。本番と同じ「公開しない・RDS を使わない」制約は崩さない |

構成を簡単にし、月額を抑える選択です。その代わり、この 1 台のディスク障害や誤削除でデータが消えるリスクがあります。

## 9. 運用で利用者がやること

運用担当は外部の情シスではなく、**利用者本人**です。監視メールや 24 時間当番はありません。画面が開かないことで気づく前提です。

| 場面 | やること |
| --- | --- |
| 普段 | Tailscale を端末でつなぎ、`http://seaweed/` を開いてログイン |
| 起動・停止 | サーバ上の手順（運用設計書）。再起動すると再ログインが必要 |
| パスワードを変える | 画面ではなく、サーバの設定ファイルを直して再起動 |
| SSH できなくなった | AWS コンソールで、SSH 許可の送信元 IP をいまの自宅 IP に更新 |
| 端末を増やす | Tailscale に同じ網で参加。ISP の IP が変わってもアプリ側の作業は不要 |
| バックアップ（推奨） | 週 1 回、ディスクのスナップショットを AWS 上に残す（直近 4 世代目安）。必須ではありませんが、取らないと全損がありうる |
| 初回データ | 手元資金・給与・サブスク・投資を画面から入れる |

復旧時間の約束（何時間以内に戻す等）は定めません。

## 10. 受け入れ時に確認すること

開発完了の目安です。技術的なテスト項目の全集ではありません。

- Tailscale 未接続では、公開の住所から家計の画面に入れない。
- 接続したうえで、ログインしないと家計・ダッシュボードの中身は見えない。
- ログイン後、家計・サブスク・投資・定期収入・設定が登録でき、ダッシュボードに反映される。
- クレジットカードの家計は、引落日なしでは保存できない。
- 給与を定期収入にだけ入れ、サブスクをマスタにだけ入れたとき、予測の収入・固定費に載る。同じものを家計簿に二重に書かなくても予測が立つ。
- 手元資金を入れる前はチャートが出ない。入れたあと、未来の引落がチャートに載る。
- 目標額だけのときは到達時期が出て、希望年月を入れたときだけ削減額が出る。
- 投資は投入総額までで、時価は出ない。
- パスワード変更のメニューがない。
- `http://seaweed/` で開ける。独自ドメインや南京錠つき公開サイトは求めない。
