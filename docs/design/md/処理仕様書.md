## 1. 前提

| 項目 | 決め |
| --- | --- |
| 時計 | `ZoneId.of("Asia/Tokyo")`。`today = LocalDate.now(zone)` |
| 金額演算 | `BigDecimal`。出力は小数 2 桁、`RoundingMode.HALF_UP`（以下「円丸め」） |
| 読み取り専用 | 本処理は INSERT/UPDATE/DELETE しない |
| 投資記録 | 予測残高に足さない。投入総額の表示のみ |
| 家計の収入 | 期間サマリには入れる。月次貯金額の収入側には入れない |
| 二重計上 | サブスク・定期収入を家計へ複製しない。予測はマスタ＋家計支出平均 |

クエリ `from`/`to` は実績ブロックだけに使う。省略時は `YearMonth.from(today)` の 1 日と末日。

## 2. 符号と月額換算

### 2.1 家計の符号付き金額

```
signed(row) =
  income  → +amount
  expense → −amount
```

### 2.2 月額換算 `monthlyEquivalent(amount, cycle)`

```
monthly  → amount を円丸め（既に 2 桁ならそのまま）
yearly   → amount.divide(12, 2, HALF_UP)
```

応答の `monthlyEquivalent`（サブスク・定期収入）と、下の合計に使う。

## 3. 実績（期間サマリ・内訳）

期間は `settled_on` の閉区間 `[from, to]`。

```
incomeTotal  = SUM(amount) WHERE kind=income  AND from ≤ settled_on ≤ to
expenseTotal = SUM(amount) WHERE kind=expense AND from ≤ settled_on ≤ to
net          = incomeTotal − expenseTotal   （円丸め）
```

ヒット 0 件なら各 0.00。

**支出内訳**

```
category ごとに SUM(amount) WHERE kind=expense AND from ≤ settled_on ≤ to
合計が 0 の費目は載せない
amount 降順。同額は category の文字列昇順
```

要素: `{ "category": "<code>", "amount": <円丸め> }`。

## 4. マスタ合計と投資要約

```
incomeMonthlyTotal        = Σ monthlyEquivalent(recurring_income)
subscriptionMonthlyTotal  = Σ monthlyEquivalent(subscription)
investmentSummary.count   = COUNT(*) FROM investment_record
investedTotal             = Σ (unit_price × quantity) を円丸め
```

行 0 なら合計 0、件数 0。

## 5. 月次貯金額

### 5.1 完了暦月ウィンドウ

今日の年月を `YmNow = YearMonth.from(today)` とする。

直近 3 完了暦月:

```
M1 = YmNow.minusMonths(3)   // 例: today=2026-08-30 → 2026-05
M2 = YmNow.minusMonths(2)   // 2026-06
M3 = YmNow.minusMonths(1)   // 2026-07
W  = {M1, M2, M3}
```

当月（YmNow）は入れない。

月 M に支出実績がある ⇔ `kind=expense` かつ `YearMonth.from(settled_on)=M` の行が 1 件以上。

```
n = W のうち実績がある月の数   // 0..3
S = W に settled_on が属する expense の amount 合計
```

### 5.2 変動費とフラグ

```
n = 0  → variableExpense = 0, variableExpenseMissing = true
n ≥ 1  → variableExpense = S.divide(n, 2, HALF_UP), variableExpenseMissing = false
```

空の月は分子に 0、分母の n にも数えない（「ある完了月だけで平均」）。

### 5.3 貯金額

```
monthlyIncome    = incomeMonthlyTotal
monthlyFixed     = subscriptionMonthlyTotal
monthlyVariable  = variableExpense
monthlySavings   = (monthlyIncome − monthlyFixed − monthlyVariable) を円丸め
```

負になりうる。

## 6. 手元資金の登録判定

`cash_on_hand` は常に 1 行。

```
registered ⇔ updated_on IS NOT NULL
originDate = updated_on          // registered のときだけ使う
originYm   = YearMonth.from(originDate)
手元資金    = amount
```

`registered == false`（初期行: amount=0, updated_on NULL）:

- `forecast.available = false`
- `forecast.points = []`
- `forecast.monthlySavings` と `variableExpenseMissing` は 5 章どおり入れる（チャート以外の説明用）
- 到達・逆算は出さない（8・9 章で `reachStatus=none`, `cutStatus=none`）

PUT `/settings/balance` 成功時、`updated_on = today`（JST）。これが次の GET の起点日になる。家計の INSERT では `updated_on` を変えない。

## 7. 予測チャート

`registered == false` なら本章の点列は作らない。

### 7.1 点の個数と時刻

起点月を含め **24 点**。`i = 0 .. 23`。

```
ym = originYm.plusMonths(i)
t  = ym の末日            // i=0 も末日（起点日より後の当月決済を同じ月の点に載せる）
k  = i                    // 経過完了月数。起点月は 0
```

`yearMonth` は `ym` の `YYYY-MM`。

### 7.2 残高

```
cf(t) = Σ signed(ledger_entry) WHERE originDate < settled_on ≤ t
amount(i) = 手元資金 + cf(t) + monthlySavings × k
          を円丸め
```

`monthlySavings × k` は `monthlySavings.multiply(BigDecimal.valueOf(k))` のあと円丸めは点の最後で 1 回。

確定分にサブスク・定期収入マスタは加えない（月次貯金額側）。`investment_record` は加えない。

見込と確定の重なりは補正しない（要件の既知の限界）。

## 8. 到達時期

入力: `savings_goal.target_amount` を `Y`、`target_on` を希望日。

```
hasGoal = (Y IS NOT NULL)
```

次のいずれかなら `reachStatus = none`, `reachYearMonth = null`:

- `registered == false`
- `hasGoal == false`

それ以外:

```
adjustedCash = 手元資金 + Σ signed(ledger) WHERE settled_on > originDate
               を円丸め
```

（希望の有無に関係なく、起点より後の家計をすべて織り込む。）

| 条件 | reachStatus | reachYearMonth |
| --- | --- | --- |
| Y ≤ adjustedCash | `achieved` | null |
| monthlySavings ≤ 0 | `unreachable` | null |
| それ以外 | `reachable` | `originYm.plusMonths(N)` |

```
N = ceil((Y − adjustedCash) / monthlySavings)
  = (Y − adjustedCash).divide(monthlySavings, 0, RoundingMode.UP)
```

`N` は 1 以上の整数。`reachYearMonth` は `YYYY-MM`。

## 9. 逆算

```
hasTargetDate = hasGoal && target_on IS NOT NULL && registered
```

`hasTargetDate == false` → `cutStatus = none`, `cutAmount = null`。

`hasTargetDate == true` でも次は逆算しない（`cutStatus = none`, `cutAmount = null`）:

- `reachStatus == achieved`（Y ≤ adjustedCash）
- `T ≤ 0`

```
T = originYm から YearMonth.from(target_on) までの月数
  = originYm.until(YearMonth.from(target_on))
```

同じ月なら T=0。過去月なら負。

逆算する場合（hasTargetDate、T>0、Y > adjustedCash）:

```
needed = (Y − adjustedCash).divide(T, 2, HALF_UP)
cut    = needed − monthlySavings    を円丸め
```

| cut | cutStatus | cutAmount |
| --- | --- | --- |
| > 0 | `needed` | cut |
| ≤ 0 | `already_ok` | **0** |

`monthlySavings ≤ 0` でも T>0 かつ未達成なら逆算する（必要な貯金額との差が大きく出る）。

目標なしで `target_on` だけある行は `hasGoal=false` のため到達も逆算も出さない。値は設定 API どおり保存したままでよい。

## 10. CRUD のうち計算に効く検証

API の 400 と重複するが、計算が壊れないためのサーバ必須。

| 対象 | 規則 | 効く計算 |
| --- | --- | --- |
| 家計 amount | > 0。符号は kind だけ | cf、サマリ、変動費 |
| 家計 settled_on | NOT NULL | 期間・完了月・チャート |
| 定期収入・サブスク amount | > 0 | 月額換算 |
| cycle=yearly | ÷12 | 固定費・収入見込 |
| 投資 unit_price, quantity | > 0。積は保存しない | investedTotal のみ |
| 手元資金 amount | ≥ 0 | 起点 |
| 目標 Y | NULL または > 0 | 到達・逆算 |
| 目標 target_on | NULL またはその月の 1 日 | T |

家計の収入を予測の収入に足してはならない。投資行の増減で `points` を変えてはならない。

## 11. 実装手順（擬似）

`DashboardService.build(from, to)`:

1. `today` を決める。`from`/`to` 省略時は当月 1 日〜末日。片方だけは API が 400。
2. 3 章のサマリ・内訳。
3. 4 章のマスタ合計・投資。
4. 5 章の `monthlySavings`, `variableExpenseMissing`。
5. `cash_on_hand` を読む。`balance.amount` / `balance.updatedOn` を埋める。
6. 6 章。未登録なら `forecast.available=false`, `points=[]`。登録済みなら 7 章で 24 点、`available=true`。
7. 8・9 章で `goalProjection`。
8. JSON キーは API設計書 11 章。欠け・別名禁止。

クラスは `com.seaweed.dashboard`。他パッケージのリポジトリを読むだけ。

## 12. 設計判断一覧

| ID | 判断 | 理由 |
| --- | --- | --- |
| D-PR-01 | 年額÷12 は HALF_UP・小数 2 桁 | 円表示と API number を一致させる |
| D-PR-02 | 変動費の分母は実績のある完了月だけ | 利用開始直後に 0 月で薄めない |
| D-PR-03 | チャートは起点月＋23 ヶ月の月末 24 点 | 月次で足り、3 年弱見られる |
| D-PR-04 | i=0 の t は起点月の末日 | 同月の未来決済を最初の点に載せる |
| D-PR-05 | 経過月数 k=i（日割りしない） | 要件の「v1 は月次」 |
| D-PR-06 | 到達の N は divide(..., 0, UP) | 正の ceil |
| D-PR-07 | T は YearMonth.until | 希望の日は常に 01 なので月差で足りる |
| D-PR-08 | 未登録でも monthlySavings は計算する | カードの定期収入・サブスク説明用。チャートは available=false |
| D-PR-09 | already_ok の cutAmount は 0 | API の「0 を返す」 |
| D-PR-10 | 確定と見込の重なりは補正しない | 要件の v1 限界 |
