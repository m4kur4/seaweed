## 1. 方針

防御は 2 段とする。

1. **網:** Tailscale 閉域。アプリは `127.0.0.1:8080` のみ待受。インターネットに HTTP/HTTPS を出さない。
2. **アプリ:** 識別子＋パスワードのセッション。業務 API は未ログイン 401 JSON。SPA の HTML は匿名 GET 可。データは API だけが守る。

WAF、公開証明書、ALB、RDS、許可 IP リスト、ユーザー表は持たない。ロール差はない。403 は返さない。

## 2. 到達制御（アプリ外）

アプリは送信元 IP を見ない。`X-Forwarded-For` で拒否しない。許可 IP フィルタ（FR-AUTH-02）は実装しない。

| 層 | 決め | 詳細 |
| --- | --- | --- |
| 待受 | `127.0.0.1:8080` | パブリック NIC に出さない（D-SYS-02） |
| 入口 | Tailscale Serve :80 → `127.0.0.1:8080` | 利用者 URL `http://seaweed/` |
| SG | 8080・3306 を `0.0.0.0/0` に開けない。SSH は送信元制限 | ルールの CIDR はインフラ設計書（NFR-SEC-06） |
| 公開 TLS | **採用しない** | Let's Encrypt、ACM、独自ドメイン、閉域内 HTTPS 終端もしない |

端末〜EC2 の暗号化は Tailscale に任せる。閉域内のブラウザ〜Serve〜JAR は HTTP 平文でよい（NFR-SEC-04）。そのため Cookie の Secure は付けない。HSTS も付けない。

## 3. アカウントと起動時検証

| 項目 | 決め |
| --- | --- |
| 件数 | 1。環境変数 `SEAWEED_AUTH_USERNAME` |
| 保存 | 環境変数のみ。`users` 表は**作らない**（D-SYS-08 を維持。覆さない） |
| 変更 | 画面・API なし（FR-AUTH-07 / OUT-01）。`/etc/seaweed/seaweed.env` を編集して `systemctl restart seaweed`（手順の全文は運用設計書） |
| リセットメール | なし |

Spring での読み方（キー名はシステム構成のまま）:

```yaml
seaweed:
  auth:
    username: ${SEAWEED_AUTH_USERNAME}
    password-hash: ${SEAWEED_AUTH_PASSWORD_HASH}
```

`@ConfigurationProperties(prefix = "seaweed.auth")`。ローカルは `application-local.yml` に同じキーを直書きしてよい（Git 禁止。example のみ可）。

**起動時（Fail fast）:** 次のいずれかならプロセスを落とす。プレースホルダのまま本番起動しない。

- `username` が null、空、または trim 後空
- `password-hash` が null / 空
- ハッシュが BCrypt 形式でない（次の正規表現に一致しない）

```text
^\$2[abxy]\$\d{2}\$[./A-Za-z0-9]{53}$
```

プロファイル `prod` では、ユーザー名が `changeme`（大小無視）なら同様に起動失敗。

## 4. パスワードハッシュ

| 項目 | 決め |
| --- | --- |
| アルゴリズム | BCrypt。Spring `BCryptPasswordEncoder` |
| ストレングス | **12**（ハッシュ先頭が `$2a$12$` / `$2b$12$` / `$2y$12$`） |
| 平文 | 環境変数・YAML・DB・ログ・例外メッセージに置かない |
| キー | `SEAWEED_AUTH_PASSWORD_HASH` にエンコード済み文字列全体（`$2` から末尾まで） |

照合: `encoder.matches(rawPassword, configuredHash)`。

ユーザー名が一致しなくても、**必ず**ダミーハッシュに対して `matches` を 1 回呼ぶ。その後どちらでも 401。ダミーハッシュはソース定数（起動のたびに `encode` しない）:

```text
$2b$12$2VWVkM/opqCcvXn1ZQUHYenNL73z/JZnuTBsn5ppFOK1fDaAx93Xq
```

（平文はコードにも env にも書かない。本番ハッシュと同一にしてはならない。）

BCrypt は平文 72 バイト制限。UTF-8 で 72 バイトを超えるパスワードは Encoder に渡さず失敗扱い（401）。ダミー `matches` は実施する。

ハッシュの作り方（実装・運用で 1 回。生成物だけを env に貼る）:

```text
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder(12);
System.out.println(encoder.encode("ここに平文"));
```

平文パスワードをリポジトリに残さない。コマンドの運用手順全文は運用設計書。

## 5. セッションと Cookie

サーブレットコンテナの `HttpSession`（メモリ）。Spring Session / Redis は使わない。プロセス再起動で全セッション無効。同時セッション数の上限は設けない。

セッション追跡は Cookie のみ。URL に `;jsessionid=` を付けない。

| Cookie 項目 | 値 |
| --- | --- |
| Name | `SEAWEED_SESSION` |
| Path | `/` |
| Domain | **設定しない**（ホストオンリー。`seaweed` / `127.0.0.1`） |
| HttpOnly | true |
| Secure | **false** |
| SameSite | `Lax` |
| Max-Age | 14 日（1209600 秒）。ブラウザ終了では消えない |

`application-prod.yml` / `application.yml` に書く値（秘密ではない）:

```yaml
server:
  servlet:
    session:
      timeout: 14d
      tracking-modes: cookie
      cookie:
        name: SEAWEED_SESSION
        path: /
        http-only: true
        secure: false
        same-site: lax
        max-age: 14d
```

| 期限 | 動き |
| --- | --- |
| サーバ `timeout` | 最終アクセスから 14 日（スライディング） |
| Cookie Max-Age | ログイン時から 14 日（アクセスしても Cookie 期限は延びない） |
| 先に切れた方 | 無効。Cookie だけ残ってサーバが切れていれば 401。新規セッションは作らない |

ログイン成功時はセッション ID を更新する（固定化対策。`HttpServletRequest.changeSessionId()`）。既存セッションがあれば invalidate してから新規作成し、そのうえで changeSessionId。

認証状態の置き場: Spring Security の `SecurityContext`。3 引数の `UsernamePasswordAuthenticationToken(username, null, List.of())`（credentials は null。ロールは付けない）。`HttpSessionSecurityContextRepository` の既定キーでセッションに格納する。独自属性名は使わない。

フロントの `fetch` / axios は `credentials: "include"`。`Authorization` ヘッダは使わない。

ローカル Vite プロキシは `Set-Cookie` をブラウザへそのまま返す。ブラウザのオリジンは `http://127.0.0.1:5173`。Cookie の Path は `/`。

## 6. Spring Security の規則

`SecurityFilterChain` 1 本。`formLogin` / `httpBasic` の既定は使わない。JSON API に合わせる。CSRF は disable（8 章）。セッション生成は `IF_REQUIRED`。health ではセッションを作らない（コントローラがセッションに触らない）。

マッチャは上から先勝ち。

| 順 | マッチャ | 結果 |
| --- | --- | --- |
| 1 | `GET /api/v1/health` | permitAll |
| 2 | `POST /api/v1/auth/login` | permitAll |
| 3 | `/api/v1/**` | authenticated |
| 4 | それ以外 | permitAll（SPA GET、静的ファイル） |

未認証で 3 に来た場合: **401 JSON**。302 で `/login` に送らない（SPA が画面設計 1.2 で遷移する）。`AuthenticationEntryPoint` を JSON 化する。`AccessDeniedHandler` は定義してよいが、認可差がないため 403 は到達させない。

401 の本文（API設計書の形。`fields` は付けない）:

| とき | HTTP | code | message |
| --- | --- | --- | --- |
| ログイン失敗（空・不一致・過長を含む） | 401 | `UNAUTHORIZED` | ユーザー名またはパスワードが正しくありません |
| 保護 API が未ログイン / セッション切れ | 401 | `UNAUTHORIZED` | ログインが必要です |

例外の JSON 化は `com.seaweed.web`。認証エントリポイントも同じ形。

パッケージ: `com.seaweed.auth` に Encoder Bean、ログイン処理、ログアウト、起動時検証。`SecurityFilterChain` は `com.seaweed.web` でも `com.seaweed.auth` でも可。1 か所にまとめる。

## 7. ログイン・ログアウト・me

パス・ステータス・ボディのキーは API設計書と同一。本書類は手順と例外だけを足す。

### 7.1 POST `/api/v1/auth/login`

認証不要。`Content-Type: application/json`。未知 JSON キーは他 API と同じく 400 `VALIDATION_ERROR`（ログイン失敗の隠蔽より、契約違反を先に落とす）。

手順:

1. ボディの `username` / `password` を文字列として読む。欠落・null は空文字と同じ。
2. 両方を trim。空、またはユーザー名が 128 文字超、またはパスワードの UTF-8 バイト数が 72 超 → ダミー `matches` のうえ **401**（400 にしない。情報を増やさない。他 API の「trim 後空は必須違反」はログインには適用しない）。
3. ユーザー名を UTF-8 バイトで `MessageDigest.isEqual`。長さが違えば false（その場合も 4 を行う）。
4. ユーザー名一致なら設定ハッシュ、不一致ならダミーハッシュで `matches`。
5. 失敗: 401、6 章のログイン失敗メッセージ。ユーザーの有無は区別しない。
6. 成功: 既存セッション invalidate → 新規セッション → `changeSessionId` → SecurityContext にユーザー名を格納 → 200 `{ "username": "<設定値>" }` と `Set-Cookie: SEAWEED_SESSION=...`（5 章の属性）。

アカウントロック・CAPTCHA・失敗回数の上限は実装しない。

### 7.2 POST `/api/v1/auth/logout`

認証必要。ボディなし。`session.invalidate()` と `SecurityContextHolder.clearContext()`。Cookie を Max-Age=0 で削除:

```text
Set-Cookie: SEAWEED_SESSION=; Path=/; Max-Age=0; HttpOnly; SameSite=Lax
```

成功 204。未認証は 401（「ログインが必要です」）。

### 7.3 GET `/api/v1/auth/me`

認証必要。200 `{ "username": "<設定値>" }`。無ければ 401（「ログインが必要です」）。

## 8. HTTP ヘッダと CSRF

| ヘッダ | 対象 | 値 |
| --- | --- | --- |
| X-Content-Type-Options | 全体 | nosniff |
| X-Frame-Options | 全体 | DENY |
| Cache-Control | `/api/v1/**` のみ | `no-store` |
| Strict-Transport-Security | — | **付けない**（HTTPS でない。Spring 既定の HSTS も無効化） |

CORS 設定はしない（同一オリジン。システム構成 3.3）。

CSRF トークンは **無効**（D-API-08 を本書類でも確定。追加しない）。`http.csrf(csrf -> csrf.disable())`。

## 9. ログと失敗

| 事象 | レベル | 内容 |
| --- | --- | --- |
| ログイン成功 | INFO | ユーザー名のみ |
| ログイン失敗 | WARN | ユーザー名（入力値。trim 後）。パスワードもハッシュも出さない |
| 保護 API の 401 | DEBUG | パスのみ。本文にスタックを載せない |
| 起動時の認証設定不備 | ERROR | どのキーが空／形式不正か。ハッシュ文字列は出さない |

5xx の `message` は「サーバエラーです」。例外詳細はサーバログのみ。

## 10. 秘密情報

| 置き場 | 内容 | Git |
| --- | --- | --- |
| `/etc/seaweed/seaweed.env` | 本番。権限 640、所有者 `root:seaweed` | 含めない |
| `application-local.yml` | ローカル用 DB パスワードと BCrypt 済みハッシュ | 含めない |
| `application-local.yml.example` | ダミーハッシュと、平文はローカル専用である旨の注記 | 含めてよい |

`application-prod.yml` にパスワード・ハッシュを書かない。5 章の Cookie 設定は書いてよい。

DB 接続ユーザー `seaweed` は localhost のみ（システム構成）。アプリに MySQL 管理者パスワードを持たせない。`SPRING_DATASOURCE_PASSWORD` も本 env に置く（キー名はシステム構成。本書類は認証ハッシュの扱いを正とする）。

| 要件 | 本書類での決め |

## 12. 明示的にやらないこと

本書類の範囲外、または要件の対象外。他文書へ委譲するものは一文だけ残す。

- 公開 TLS / Let's Encrypt / ACM / 独自ドメイン / 閉域内 HTTPS
- アプリの許可 IP、Basic 認証の二重化
- MFA、OAuth、JWT、`Authorization` ヘッダ
- パスワード変更・リセット API
- アカウントロック、失敗 N 回での拒否、CAPTCHA
- ユーザ表、権限ロール、403
- ペネトレーションテスト、WAF、監査ログ基盤
- CSRF トークン（D-API-08 を覆さない）

SSH の鍵・SG の具体 CIDR はインフラ設計書。バックアップと env 差し替え手順は運用設計書。

## 13. 設計判断一覧

| ID | 判断 | 理由 |
| --- | --- | --- |
| D-SEC-01 | 公開 TLS 非採用。Cookie Secure=false。HSTS なし | NFR-SEC-04。閉域 HTTP |
| D-SEC-02 | BCrypt 強度 12、env にハッシュのみ | NFR-SEC-03。個人利用で十分遅く、平文を残さない |
| D-SEC-03 | メモリセッション 14 日、Cookie 名 `SEAWEED_SESSION`、ブラウザ終了では消さない | FR-AUTH-04 の「一定期間」。再起動で全部切れる単純さ |
| D-SEC-04 | SPA GET は匿名、API だけ守る | 静的ファイルに認証を掛けない。データ漏洩面は API |
| D-SEC-05 | 未認証 API は 401 JSON。302 しない | SPA と API設計書 |
| D-SEC-06 | CSRF disable を確定 | D-API-08。閉域・同一オリジン |
| D-SEC-07 | ユーザー名不一致でも BCrypt を実行。ダミーハッシュは定数 | タイミング差を減らす。起動ごとに encode しない |
| D-SEC-08 | ロックなし | NFR-SEC-05。閉域前提 |
| D-SEC-09 | ユーザ表を作らない | D-SYS-08 を覆さない |
| D-SEC-10 | ログインの空欄は 400 ではなく 401 | 必須項目の有無でアカウント存在を推測させない |
| D-SEC-11 | 403 を使わない | ロール差がない。失敗は 401 か業務の 4xx |
