## 1. 共通規則

| 項目 | 決め |
| --- | --- |
| 格納 | UTF-8 の英小文字・数字・アンダースコア。日本語はラベルのみ |
| API | リクエスト・レスポンスとも本書類の `code` 列 |
| DB | コードマスタ表は置かない。業務テーブルの列に VARCHAR で直書き。長さは 9 章 |
| 未知値 | API は 400。DB 制約はテーブル定義書（CHECK またはアプリ検証） |
| 追加 | v1 で値を増やさない。増やすときは本書類・API・画面を同時改訂 |
| 並び | 画面の select は表の **No 昇順**。内訳グラフは金額順（コード順ではない） |

Java: 各区分は enum。`@JsonValue` は `code`。TypeScript: 下記のユニオン型を `frontend/src/codes.ts` に置く。

## 2. KIND 収支区分

列: `ledger_entry.kind`  
JSON: `kind`  
型名: `Kind`

| No | code | ラベル | 備考 |
| --- | --- | --- | --- |
| 1 | `expense` | 支出 | 新規フォームの初期値 |
| 2 | `income` | 収入 | 家計簿の臨時収入 |

給与の見込みは本区分に載せない（定期収入マスタ）。

## 3. PAYMENT_METHOD 支払手段

列: `ledger_entry.payment_method`  
JSON: `paymentMethod`  
型名: `PaymentMethod`

| No | code | ラベル | 資金決済日（画面。サーバは常に日付必須） |
| --- | --- | --- | --- |
| 1 | `cash` | 現金 | 発生日に追従 |
| 2 | `bank` | 銀行口座 | 発生日に追従 |
| 3 | `credit_card` | クレジットカード | 空可にせず必須。欠落は 400 |
| 4 | `e_money` | 電子マネー・QR | 発生日に追従 |
| 5 | `other` | その他 | 発生日に追従 |

新規フォームの初期値は `cash`。

## 4. CATEGORY 費目

列: `ledger_entry.category`  
JSON: `category`  
型名: `Category`

`kind` との組み合わせ以外は 400。

### 4.1 kind = expense

| No | code | ラベル | 目安 |
| --- | --- | --- | --- |
| 1 | `housing` | 住居 | 家賃、住宅ローン、管理費 |
| 2 | `food` | 食費 | 食料品、外食 |
| 3 | `daily` | 日用品 | 消耗品、雑貨 |
| 4 | `utilities` | 水道光熱 | 電気・ガス・水道 |
| 5 | `telecom` | 通信 | スマホ等。サブスクマスタに載せるものは家計に書かない |
| 6 | `transport` | 交通 | 電車、バス、ガソリン |
| 7 | `medical` | 医療 | 病院、薬 |
| 8 | `education` | 教育 | 書籍、習い事 |
| 9 | `clothing` | 衣服 | 衣類、靴 |
| 10 | `leisure` | 交際・娯楽 | 趣味、旅行、交際費 |
| 11 | `investment_transfer` | 投資拠出 | 証券口座への入金。投資記録とは別 |
| 12 | `other` | その他 | 上記以外 |

`other` は支出のその他。収入の `other_income` とコードを分ける。

### 4.2 kind = income

| No | code | ラベル | 目安 |
| --- | --- | --- | --- |
| 1 | `extra` | 臨時収入 | 還付、贈与、売得 |
| 2 | `other_income` | その他収入 | 上記以外 |

`salary` は定義しない。

### 4.3 許可マトリクス

| category | expense | income |
| --- | --- | --- |
| housing … investment_transfer, other（4.1） | 可 | 不可 |
| extra, other_income | 不可 | 可 |

ダッシュボード内訳の `category` は 4.1 のみ（支出合計）。

## 5. CYCLE 周期

列: `subscription.cycle`, `recurring_income.cycle`  
JSON: `cycle`  
型名: `Cycle`

| No | code | ラベル | 月額換算（処理仕様の入力。式は処理仕様書） |
| --- | --- | --- | --- |
| 1 | `monthly` | 月額 | 金額そのまま |
| 2 | `yearly` | 年額 | 金額 ÷ 12 |

新規の初期値は `monthly`。

`billingMonth` / `billingDay` の組み合わせ規則は API設計書 7 章。本書類のコードではない。

## 6. DATE_FIELD 家計一覧の日付種類

DB 列ではない。クエリ `dateField` のみ。  
型名: `DateField`

| No | code | ラベル | フィルタ列 |
| --- | --- | --- | --- |
| 1 | `occurred` | 発生日 | `occurred_on` |
| 2 | `settled` | 資金決済日 | `settled_on` |

画面初期値は `settled`。

## 7. 応答専用コード

永続化しない。API 応答の enum。処理仕様書がどの値を返すかを決める。

### 7.1 エラー `code`

| code | HTTP |
| --- | --- |
| `VALIDATION_ERROR` | 400 |
| `LIMIT_EXCEEDED` | 400 |
| `UNAUTHORIZED` | 401 |
| `NOT_FOUND` | 404 |
| `INTERNAL` | 500 |

### 7.2 health `status`

| code | 意味 |
| --- | --- |
| `ok` | プロセス生存 |

### 7.3 reachStatus

| code | 画面の目安 |
| --- | --- |
| `none` | 目標なし。到達ブロックを出さない |
| `reachable` | YYYY年M月頃 |
| `unreachable` | 到達不可 |
| `achieved` | 達成済み |

### 7.4 cutStatus

| code | 画面の目安 |
| --- | --- |
| `none` | 逆算しない（希望日なし等） |
| `needed` | 削減額を表示 |
| `already_ok` | 現状のままで達成可能 |

## 9. 実装対応

### 9.1 DB 列の長さ（テーブル定義書へ）

未知の延長を防ぐため、格納幅を固定する。

| 列 | VARCHAR |
| --- | --- |
| kind | 16 |
| payment_method | 16 |
| category | 32 |
| cycle | 16 |

実コードの最長は `investment_transfer`（20 文字）なので category は 32 で足りる。

### 9.2 TypeScript（実装時の型名）

```ts
export type Kind = "expense" | "income";
export type PaymentMethod = "cash" | "bank" | "credit_card" | "e_money" | "other";
export type ExpenseCategory =
  | "housing" | "food" | "daily" | "utilities" | "telecom" | "transport"
  | "medical" | "education" | "clothing" | "leisure" | "investment_transfer" | "other";
export type IncomeCategory = "extra" | "other_income";
export type Category = ExpenseCategory | IncomeCategory;
export type Cycle = "monthly" | "yearly";
export type DateField = "occurred" | "settled";
```

select の options 配列は本書類の No 順。ラベルは本書類のラベル列をハードコードしてよい（API からコードマスタは取らない）。

### 9.3 Java enum 名

| 型 | 定数例 |
| --- | --- |
| `Kind` | `EXPENSE("expense")`, `INCOME("income")` |
| `PaymentMethod` | `CASH`, `BANK`, `CREDIT_CARD`, `E_MONEY`, `OTHER` |
| `Category` | `HOUSING`, … `INVESTMENT_TRANSFER`, `OTHER`, `EXTRA`, `OTHER_INCOME` |
| `Cycle` | `MONTHLY`, `YEARLY` |
| `DateField` | `OCCURRED`, `SETTLED` |

`Category.OTHER` は支出。収入はその他を `OTHER_INCOME` にする（定数名の衝突回避）。

## 10. 設計判断一覧

| ID | 判断 | 理由 |
| --- | --- | --- |
| D-CD-01 | コードマスタテーブルなし | 固定・1 ユーザー。JOIN と編集画面を避ける |
| D-CD-02 | API と DB で文字列を一致 | 変換層を作らない |
| D-CD-03 | 支出その他は `other`、収入は `other_income` | 同一 VARCHAR 列で kind なしだと衝突する |
| D-CD-04 | 給与コードを置かない | 定期収入へ誘導する要件をコードで強制する |
| D-CD-05 | 画面ラベルはフロントに持つ | コード取得 API を増やさない |
